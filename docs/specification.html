Specification

記法と生成仕様

FlowClozeのMarkdown記法，target type，中間JSON，生成JSONの要点をまとめています．

Markdown記法

qblock

問題化したい範囲を #qblock{ ... } で囲みます．IDは出現順に自動採番されます．

target

答えにしたい語句を [答え] で囲みます．必要に応じて [答え]{type} と書けます．

section

Markdownの見出し1だけを単元見出しとして扱います．

blank

生成される問題文では，空欄に ＿＿＿ を使います．

# ソフトウェア工学の概論

#qblock{
- [QCD]{term-name}は[品質]{meaning}，[コスト]{meaning}，[納期]{meaning}を表す．
}

target type

typeは「その語句をどの観点で問いたいか」を示すラベルです．未定義typeも抽出されますが，中間JSONのwarningsに警告が入ります．

type 説明
term-name 用語名そのものを問う
meaning 意味，定義，性質，目的などを問う
process 手順，工程，動作，状態変化などを問う
relation 構成，比較，分類，関係，対応などを問う

生成と検証

中間JSON

Markdownからqblock，section，source_text，targets，warningsを抽出します．

QuestionComposer Core

プロバイダはtask IDとquestion本文だけを返し，CoreがID照合，retry，検証，固定フィールドの再構築を担当します．

検証

空欄数とanswers数，targetsとの一致，answer漏出，IDの重複・不足・未知，順序，固定フィールドを確認します．

生成経路の保証

parserはtargetのUTF-8 spanを確認し、Coreは文書内で衝突しないsentinelを各targetに割り当てます。プロバイダ出力ではsentinelの欠落、重複、順序変更、未知tokenを検出してから標準空欄へ戻すため、answerと空欄の対応を内部で保証します。

最終JSONは常に既存の { questions: [...] } schemaです。section、type、targets、answers、source_textは中間JSONから再構築し、プロバイダ由来なのはquestion本文だけです。fallbackや観測メタデータは最終JSONに追加しません。

内容不正はtask単位で最大2回再試行します。fallback=error は失敗を返し、fallback=draft は通信系または内容検証系で失敗したtaskだけをIdentity下書きに戻します。ID・固定フィールド・順序の対応付けが不正な失敗はstrictに返します。

generate の設定はCLI、canonical環境変数、対応するlegacy環境変数、config.toml、既定値の順に解決します。--provider（--backend は別名）、--model、--rewrite、--fallback、--structured-output を使えます。rewrite=never はプロバイダを呼ばないIdentity生成です。

HTTP API

HTTP APIとして実装する場合の契約はOpenAPIで管理します．詳細は APIドキュメント を参照してください．
