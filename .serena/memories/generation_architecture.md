Stable Phase 1-5 generation contract:
- Core owns Parser/Assembler truth: opaque Core IDs, qblock/task order, section/type/targets/answers/source_text and every fixed GeneratedDocument field. QuestionComposer is a domain port, not generic LLM plumbing; batch is in the contract. Composer/provider may change only question text and must echo IDs; provider metadata never enters public GeneratedDocument JSON.
- Planner creates batch requests, retains confirmed tasks, and retries only failed tasks. Transport/provider failures and content failures are separate: bounded HTTP retry for rate-limit/timeout/transport/retryable API; parse/empty/validation failures use task-level content retry with feedback. No document-wide regeneration.
- Strict merge/validation rejects unknown, duplicate, missing or mutated IDs, count/order mismatch, fixed-field changes, blank/sentinel mismatch and answer leakage; no silent `filter_map` loss. `fallback=draft` is explicit, preserves successful tasks, and drafts only exhausted eligible failures; document-integrity errors remain fatal. Default is strict/error.
- Located generation privately parses raw qblock target byte spans, uses document-wide FNV-derived sentinel namespace/tokens, distinguishes source-existing complete FC tokens from generated tokens, validates sentinel set/order/duplicates/foreign namespace, then normalizes to `＿＿＿`. Legacy parser/scaffold and JSON APIs remain compatibility paths; typed validation is authoritative.
- Provider adapters own HTTP envelopes, auth/base URL/model differences and conversion to common ComposeError. Structured output (`auto|on|off`) is a capability optimization, never a validation substitute: schema parse and validation remain mandatory; unsupported schema may downgrade once to plain JSON. Config precedence is CLI > canonical env > legacy env > config.toml > defaults; empty env is unset; secrets use lazy `api_key_env` indirection, not config values.
- Observability is redacted JSONL: run/batch/task/attempt, provider/model/prompt version and FNV hashes, latency, sizes, error/retry/fallback class; never source/question/answer/prompt/API key. Execution remains sequential even when concurrency config is validated/observed.
- Tests should use Identity and HTTP mocks for deterministic Core/port/adapter/planner coverage; real provider live smoke is optional/ignored, not CI-required. See `mem:phase4_located_generation`, `mem:provider_adapters`, `mem:generation_config`, `mem:generation_review_invariants`, `mem:observability` for focused details.
