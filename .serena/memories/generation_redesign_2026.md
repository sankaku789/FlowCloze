Generation redesign completed on `future/component`. Batch planning is physically in `src/generation/planner.rs`; provider execution, task-level content retry, successful-task retention, merge and validation are in `src/generation/executor.rs`. Public `compose_with_question_composer*` functions remain compatibility wrappers and must route through Executor.

Configuration is YAML-only: `config.yaml` for operations/quota/Typst, `model.yaml` for provider/model catalog, `auth.yaml` for secrets. Resolution is built-ins -> model.yaml -> config.yaml -> CLI -> auth. Built-ins are google, ollama, gemini-flash. Google and Ollama both use OpenAiCompatibleAdapter. Gemini native, TOML config, Provider/RewritePolicy, and CLI rewrite/structured-output/provider/backend were intentionally removed. Normal generation sends all tasks to the provider; `--offline` uses Identity for all tasks.

Physical source boundaries are `core/`, `generation/`, `application/`, `providers/`, `config/`, `runtime/`, `output/`, and `cli/`. `main.rs` is only bootstrap. Crate-root aliases preserve established parser/planner/orchestration paths; do not remove them without confirming external API compatibility.
