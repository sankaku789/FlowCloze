# 情報セキュリティの基礎

#qblock{
- 情報セキュリティでは，[機密性]{meaning}，[完全性]{meaning}，[可用性]{meaning}をまとめてCIAと呼ぶ
    + 機密性は，許可された人だけが情報へアクセスできる性質である
    + 完全性は，情報が正確で改ざんされていない性質である
    + 可用性は，必要なときに情報やシステムを利用できる性質である
- これらは互いに独立ではなく，例えば認証を強くしすぎると[可用性が低下する場合がある]{relation}
}

## 認証と認可

#qblock{
- [認証]{term-name}は，利用者が誰であるかを確認する仕組みである
- [認可]{term-name}は，認証された利用者が何をしてよいかを決める仕組みである
- 例えばログイン処理では，IDとパスワードで[本人であることを確認]し，その後に管理画面へアクセスできるかを判断する

### 多要素認証

- 多要素認証では，知識情報，所持情報，生体情報など，異なる種類の要素を組み合わせる
- パスワードだけに依存しないため，[漏えいしたパスワードだけでは侵入されにくくなる]{meaning}
}

## 暗号とハッシュ

#qblock{
- 共通鍵暗号では，暗号化と復号に[同じ鍵を使う]{process}
    + 処理は高速だが，事前に鍵を安全に共有する必要がある
- 公開鍵暗号では，暗号化と復号に[異なる鍵を使う]{process}
    + 鍵共有の問題を軽減できるが，共通鍵暗号より処理が重い
- ハッシュ関数は，入力データから固定長の値を生成する
    + 同じ入力からは同じ値が得られる
    + 逆算が困難であるため，パスワード保存では[平文パスワードそのものを保存しない]{meaning}目的で使われる
}

# 品質管理の基礎

#qblock{
- 品質管理では，完成品だけを確認するのではなく，工程の途中で問題を発見することが重要である
- [検査]{term-name}は，できあがった成果物が基準を満たしているかを確認する活動である
- [レビュー]{term-name}は，成果物を作り込む途中で第三者が内容を確認する活動である
- 対義的に，レビューを行わない開発では[問題が後工程まで残りやすく，修正コストが増える]{meaning}
}

## プロセス改善

#qblock{
- PDCAは，[計画]{process}，[実行]{process}，[評価]{process}，[改善]{process}を繰り返す考え方である
- 一度だけ改善して終わるのではなく，[継続的に改善を回し続ける]{meaning}ことに意味がある
- 評価のためには，感覚ではなく[測定可能な指標を使う]{process}
    + 例として，欠陥密度，レビュー指摘件数，テスト成功率などがある
}

# データベース設計

#qblock{
## 正規化

- 正規化は，データの重複や更新時の不整合を減らすために表を整理する考え方である
- 第1正規形では，1つのセルに複数の値を入れず，[値を原子的に扱う]{meaning}
- 第2正規形では，主キーの一部だけに依存する属性を分離し，[部分関数従属を取り除く]{process}
- 第3正規形では，主キー以外の属性に依存する属性を分離し，[推移的関数従属を取り除く]{process}
}

## トランザクション

#qblock{
- トランザクションは，複数の処理を1つのまとまりとして扱う仕組みである
- ACID特性には，[原子性]{meaning}，[一貫性]{meaning}，[独立性]{meaning}，[永続性]{meaning}がある
- 原子性とは，処理がすべて実行されるか，[まったく実行されなかった状態に戻る]{meaning}性質である
- 永続性とは，コミットされた結果が障害後も[失われずに保存される]{meaning}性質である
}

# ネットワーク基礎

#qblock{
- TCP/IPの階層モデルでは，上位層が下位層の機能を利用して通信する
- アプリケーション層では，[HTTP]{term-name}や[DNS]{term-name}などのプロトコルが使われる
- トランスポート層では，TCPとUDPが代表的である
    + TCPは[コネクションを確立して信頼性のある通信を行う]{meaning}
    + UDPは[コネクションを確立せず，低遅延な通信に向く]{meaning}
- IPアドレスはネットワーク上の機器を識別するために使われ，[宛先までパケットを届ける]{process}ための情報になる
}

## 名前解決

#qblock{
- DNSは，ドメイン名とIPアドレスを対応付ける仕組みである
- 例えば `example.com` にアクセスするとき，まず[ドメイン名からIPアドレスを調べる]{process}
- キャッシュを使うと問い合わせ回数を減らせるが，古い情報が残ると[変更後のIPアドレスへすぐに切り替わらない]{meaning}場合がある

---

- TTLはキャッシュを保持してよい時間を示す
- TTLを短くすると変更は反映されやすいが，[問い合わせ回数が増えてDNSサーバの負荷が上がる]{relation}
- TTLを長くすると負荷は下がるが，[古い名前解決結果が残りやすくなる]{relation}
}

# オペレーティングシステム

#qblock{
- プロセスは，実行中のプログラムをOSが管理する単位である
- スレッドは，プロセス内で実行される処理の流れであり，同じプロセス内の資源を共有する
- 排他制御では，複数の処理が同時に共有資源へアクセスして不整合を起こさないようにする
- [ミューテックス]{term-name}は，1つの処理だけが共有資源へ入れるようにする仕組みである
- [セマフォ]{term-name}は，利用可能な資源数をカウンタで管理し，複数個の資源を扱えるようにする仕組みである
- どちらも便利だが，使い方を誤ると[デッドロックやスタベーションが発生する]{meaning}
}

## 仮想記憶

#qblock{
- 仮想記憶では，実メモリより大きなアドレス空間をプロセスへ見せる
- ページングでは，メモリを固定長のページに分けて管理する
- ページフォールトは，参照したページが主記憶上にないときに発生する
- ページフォールトが発生すると，OSは[必要なページを補助記憶装置から読み込む]{process}
- 参照の局所性とは，プログラムが短い時間では[限られた範囲の命令やデータを繰り返し参照する]{meaning}傾向である
}

# ソフトウェア設計

#qblock{
- モジュール分割では，機能を適切な単位へ分けることで理解しやすさと変更しやすさを高める
- [凝集度]{term-name}は，1つのモジュール内部の要素がどれだけ関連しているかを表す
- [結合度]{term-name}は，モジュール同士がどれだけ依存しているかを表す
- よい設計では，一般に[凝集度を高くし，結合度を低くする]{relation}
- ただし，分割しすぎると[小さな変更でも多くのファイルを追う必要がある]{meaning}ため，読みやすさが下がる場合もある
}

## 例外処理

#qblock{
- 例外処理は，通常の処理とは異なる異常系を扱うための仕組みである
- 例外を握りつぶすと，[失敗したことが呼び出し元に伝わらない]{meaning}
- 逆に，すべての例外をそのまま上位へ投げるだけでは，[どこで回復すべきかが分かりにくくなる]{meaning}
- そのため，例外は[意味のある単位で捕捉し，必要な情報を残して扱う]{process}ことが重要である
}

# 要件定義

#qblock{
- 要件定義では，利用者が本当に必要としているものを明確にする
- ヒアリングでは，利用者が言葉にした要望だけでなく，背景にある目的も確認する
- [機能要件]{term-name}は，システムが何をするかを表す要件である
- [非機能要件]{term-name}は，性能，信頼性，保守性，セキュリティなど，システムがどのように振る舞うべきかを表す要件である
- 非機能要件は後から追加すると設計全体に影響しやすいため，[初期段階から制約として扱う]{process}必要がある
}

## 曖昧な表現

#qblock{
- 要件に「高速に」「使いやすく」のような表現だけを書くと，開発者と利用者で解釈がずれる
- そのため，要件は可能な限り[測定可能な基準で表現する]{process}
- 例えば「画面表示を高速にする」ではなく，[検索結果を2秒以内に表示する]{meaning}のように書く
- ただし，数値だけを決めても利用者の目的に合わなければ意味がないため，[数値目標と利用場面を合わせて確認する]{process}
}

# アルゴリズム

#qblock{
- 探索アルゴリズムでは，目的のデータを見つけるためにデータ構造を調べる
- 線形探索は，先頭から順に要素を確認する方法であり，データが整列していなくても使える
- 二分探索は，整列済みのデータに対して中央の値と比較し，探索範囲を半分ずつ狭める
- 二分探索を使うには，[データがあらかじめ整列している]{meaning}必要がある
- 計算量は，線形探索が[O(n)]{meaning}，二分探索が[O(log n)]{meaning}である
}

## グラフ探索

#qblock{
- グラフ探索では，頂点と辺からなる構造をたどる
- 幅優先探索は，始点から近い頂点を順に調べる
- 深さ優先探索は，行けるところまで深く進んでから戻る
- 最短経路を辺の重みなしで求める場合，幅優先探索は[始点からの辺数が最小の経路を見つけられる]{meaning}
- 一方，重み付きグラフで最短経路を求める場合は，[辺の重みを考慮するアルゴリズムが必要になる]{meaning}
}
